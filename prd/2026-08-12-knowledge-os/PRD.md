# PRD — Knowledge OS 全栈知识库系统

**分支:** 无（独立项目） · **基线:** 实际代码库 · **设计:** 代码库 → PRD 转换 · **日期:** 2026-08-12
**状态:** 已实现，PRD 为系统文档

## 概述

- Knowledge OS 是一个基于 RAG（检索增强生成）的 AI 知识库管理系统，支持文档上传与自动解析、向量化检索、LLM 智能问答、知识图谱可视化。
- 技术栈：FastAPI + PostgreSQL + pgvector（后端），React + TypeScript + Zustand + React Router v6（前端），ECharts（图谱），PostCSS 模块化 CSS。
- 系统采用三列自适应布局：左侧可折叠深色侧边栏、中间主内容区（React Router Outlet 路由切换）、右侧 Agent Operator 全局智能面板。
- 核心用户流程：创建知识库 → 上传文档（自动解析/分块/向量化/AI 分类/实体抽取/知识图谱） → 浏览文件列表 → RAG 对话问答。
- 共 4 个主路由：首页空状态引导（`/`）、KB 详情（`/kb/:id`）、知识图谱（`/graph`）、系统设置（`/settings`）。
- 后端 7 个 API 模块（kb / documents / folders / faq / rag / graph_api / admin），9 张数据表。
- RAG 管线：向量检索（pgvector）+ 关键词检索 + 实体检索 三路并行 → 查询扩展（LLM 生成 2 个变体） → 合并去重加权 → CrossEncoder 重排序 → LLM 流式生成。

> **阅读顺序说明：** 本文按产品体验叙述顺序排列 — 从壳层和导航开始，然后进入 KB 详情页面及其子功能，再到独立页面（图谱、设置），最后是全局 Operator。每个标题后的 `[构建: …]` 标注了开发实现顺序，与叙述顺序可能不同。

## C1 — 应用壳层与三列布局导航            [构建: 无依赖]

> **截图：** 待从运行系统截取 — 左侧 220px Sidebar + 中间主内容区 + 右侧 Operator 面板的三列布局。

### 改动内容

全站统一的三列布局壳层，通过 `AppLayout` 组件包裹所有路由。左侧 Sidebar 宽度 220px，深色背景（品牌色 #1f2329），全站所有页面一致可见，不可关闭。顶部显示 Knowledge OS 品牌标识——两个通过 CSS 绘制的重叠菱形 Logo + "Knowledge OS" 标题。品牌标识下方是两个可折叠的知识库分组：

- **个人知识库**（默认展开）：列出所有 `visibility != "shared"` 的 KB，每个 KB 显示名称和文档数量徽标。分组标题旁有创建按钮（悬停可见 +），点击弹出 `prompt()` 输入名称后创建。
- **共享知识库**（独立折叠）：列出所有 `visibility == "shared"` 的 KB，样式同上。

KB 子项点击后导航到 `/kb/:id` 详情页。当前活跃项有蓝色左边框和浅蓝色背景高亮。底部分隔线下方固定两个导航入口：知识图谱（GitFork 图标，路由 `/graph`）、设置（Settings 图标，路由 `/settings`）。

中间主内容区通过 React Router `<Outlet />` 渲染 4 个页面路由（Home / KB Detail / Graph / Settings），路由切换时 Sidebar 和 Operator 保持不变。

侧边栏响应式断点：>1180px 完整展开（220px），930-1180px 折叠为图标模式（56px），<760px 移动布局。全局通过 Zustand `useUIStore` 管理侧边栏和 Operator 的折叠状态及断点，`window.resize` 事件自动更新。

### 设计原因

用户通常管理多个知识库，固定侧边栏比顶部 Tab 能容纳更多 KB 条目且不占用水平空间。折叠分组让用户区分自己创建和他人分享的 KB。底部固定图标入口降低导航层级——图谱和设置始终一键可达。通过 Zustand 集中管理 UI 状态而非 useState 提升，避免跨组件 prop drilling。(*来源: inferred*)

- [ ] "个人知识库" 分组可折叠/展开，展开时箭头旋转 90°
- [ ] 每个 KB 子项显示 `BookOpen` 图标、名称、文档数量徽标
- [ ] 分组标题旁有添加按钮（悬停可见 `+`），点击弹出 prompt 对话框
- [ ] "共享知识库" 分组独立折叠，与个人知识库互不影响

## C2 — KB 详情 — 文件浏览器（文件夹导航 + 文件列表）            [构建: 需要 C1 先完成]

> **截图：** 待从运行系统截取 — 面包屑导航栏 + 文件夹/文件混合表格 + 上传下拉菜单。

### 改动内容

进入知识库详情页（`/kb/:id`）后，页面分为左右两个区域：左侧主区域包含面包屑导航 + 文件夹/文件表格 + FAQ + 推荐问题，右侧是对话面板（详见 C4）。

**顶部栏：** 显示 KB 名称（从 API 获取）和可见性标签（蓝色胶囊 "共享知识库" / "个人知识库"），右侧显示文档总数、对话面板展开/收起按钮。

**面包屑导航：** 左侧 "📂 全部文件" 按钮始终存在，点击回到根目录（`selectedFolder = null`，清除文件夹范围限定）。进入子文件夹后，以 `>` 分隔显示当前路径。右侧显示当前层级的文件数量和操作按钮：新建文件夹、上传文件（展开下拉菜单）。

**上传下拉菜单：** 四个入口：
1. 文档（`.pdf .doc .xlsx .csv .txt .md .pptx .html` 等 20+ 种格式）
2. 图片（`.png .jpg .gif .svg .webp` 等 10+ 种格式）
3. 音视频（`.mp3 .mp4 .mov .avi` 等 8+ 种格式）
4. 网页链接（弹出 URL 输入弹窗，可选标题）

**文件夹/文件表格：** 统一在同一表格中展示，7 列 CSS Grid 布局 `32px 28px 1fr 70px 60px 80px 100px`：
| 复选框 | 图标 | 名称 | 类型 | 大小 | 状态 | 操作 |

- **表头：** 第一列复选框可全选/取消全选当前可见项（文件夹 + 文件），列名固定在顶部。
- **文件夹行：** 紫色名称字体，点击进入子目录，面包屑同步更新。图标列显示 Folder 图标。大小列显示子目录数。状态列显示该文件夹包含的文件数。双击/右键显示文件夹上下文菜单。
- **文件行：** 显示对应文件图标 + 文件名 + 大写扩展名类型 + 格式化文件大小 + 解析状态（绿色"已完成"= `completed`/`classified`，灰色=其他状态）+ 操作列（标签点 + 预览按钮）。
- **空状态：** 当文件夹无文件时显示居中的空状态提示 "暂无文件，上传 PDF/Word/Markdown 开始"。
- **前端搜索：** 文件名在浏览器侧实时过滤，不请求后端。

**子文件夹展示：** 当进入根目录下某文件夹时，若该文件夹有子文件夹（`children` 字段），子文件夹也展示为独立行。

**数据刷新：** 所有数据（KB 信息、文档列表、文件夹树、FAQ 列表）在挂载时全量加载（`Promise.all`），之后每 5 秒自动轮询刷新。

**文件夹范围限定：** 点击文件夹进入子目录时，自动将 RAG 检索范围限定到该文件夹（`scopedFolderId` / `scopedFolderName`）。对话面板输入框上方显示文件夹范围标签，可点击 ✕ 清除。

### 设计原因

7 列精确 CSS Grid 控制列宽，避免传统 `<table>` 在不同内容长度下列宽不一致的问题。文件夹和文件混合在同一个列表中而非分开，降低了视觉切换成本——用户看到的始终是一个统一的内容树。5 秒轮询确保后台解析完成后前端及时更新状态。(*来源: inferred*)

### 验收要点
- [ ] 面包屑导航显示 "全部文件" 按钮（始终可见）和当前文件夹路径（以 `>` 分隔）
- [ ] 文件夹和文件在统一表格中展示，7 列精确对齐 `32px 28px 1fr 70px 60px 80px 100px`
- [ ] 文件夹名称可点击进入子目录，面包屑同步更新，行显示子目录数和文件数
- [ ] 上传按钮展开下拉菜单：文档/图片/音视频/网页链接 四个入口，点击外部关闭
- [ ] 支持 30+ 种文件格式上传（文档/图片/音视频）
- [ ] 状态列：`completed` 或 `classified` → 绿色 "已完成"，其他 → 灰色原始状态值
- [ ] 搜索框输入实时过滤文件名（前端 `filter`，不请求后端）
- [ ] 全部数据 5 秒自动轮询刷新
- [ ] 顶部栏显示 KB 名称、可见性标签（蓝色胶囊）、文档总数
- [ ] 空状态提示 "暂无文件，上传 PDF/Word/Markdown 开始"
- [ ] 底部状态栏显示：可见性图标 · 文档数 · FAQ 数 · 当前会话名
- [ ] 文件大小格式化：B/KB/MB/GB 自动进位

## C3 — KB 详情 — 文件交互（悬停提示、右键菜单、多选批量操作）            [构建: 需要 C2 先完成]

> **截图：** 待从运行系统截取 — 悬停 Tooltip + 右键上下文菜单 + 编辑标签弹窗。

### 改动内容

**悬停提示（Tooltip）：** 鼠标悬停文件行时，在鼠标附近弹出深色半透明 Tooltip 浮层（`position: fixed`，跟随 `onMouseMove` 实时更新位置）。内容从上到下依次为：
- 文件名（加粗标题）
- 类型（大写扩展名）
- 文件大小
- 上传时间（`toLocaleString("zh-CN")` 格式）
- 解析状态（绿色文字）
- AI 分类结果（来自 `classification` JSON：场景 · 类别 · 严重度）
- 用户标签（彩色胶囊样式）

**右键/双击上下文菜单：** 右键或双击文件/文件夹行时，在鼠标位置弹出白色上下文菜单（圆角 8px，盒子阴影）。菜单顶部有标题栏区分操作对象。菜单内容根据选中情况动态变化：
- **单个文件：** 重命名 → 编辑标签 → 分隔线 → 移动到 → 复制到 → 分隔线 → 删除（红色文字）
- **单个文件夹：** 重命名 → 分隔线 → 删除
- **多选（≥2 项选中时右键任意一项）：** 移动到 → 复制到 → 分隔线 → 删除
- 点击菜单外部或按 Esc 自动关闭。

**复选框多选系统：**
- 每行左侧有复选框，点击切换该项选中状态（`Set<string>` 管理选中 ID 集合）
- 表头复选框可全选/取消全选当前可见的所有项（文件夹 + 文件）
- 勾选任意项后顶部栏出现 "已选 N 项 · 取消" 提示
- 当右键菜单对象已在选中集合中时，菜单上下文自动变为多选模式（`contextMenu.ids` 包含全部选中项）

**重命名弹窗：** 模态弹窗，标题 "✏️ 重命名"，输入框预填当前名称，按 Enter 或点击确定提交 PATCH 请求（文件→`updateDocument`，文件夹→`PATCH /folders/{id}`）。

**编辑标签弹窗：** 模态弹窗，标题 "🏷 编辑标签 — 文件名"，上半部分展示当前所有标签胶囊（每个胶囊有 × 删除按钮），下半部分输入框添加新标签（回车添加）。点击保存提交 PATCH `updateDocument({ tags })`。

**预览弹窗：** 从后端获取文档详情（含 chunks），将所有 chunk 内容拼接后在模态弹窗中以 `<pre>` 纯文本展示。PDF 文件显示特殊提示 "PDF 预览需要后端渲染支持，当前显示文本提取内容"。

**批量操作分发器（移动到/复制到）：** 弹出文件夹选择器（居中模态），列出 "根目录（无文件夹）" + 所有文件夹（层级缩进显示，子文件夹 `paddingLeft` 加深 14px）。选择目标文件夹后依次调用 `updateDocument(folder_id)` 或 `copyDocument(target_folder_id)`。操作完成后显示成功 Toast。

### 设计原因

Tooltip 让用户无需点开预览就能快速了解文件元数据和 AI 分类结果——这在知识库管理场景中尤其重要，因为用户需要判断文件内容是否相关。右键菜单是桌面端最高效的文件操作方式，避免顶部工具栏按钮过多。多选+批量操作减少重复劳动。标签用胶囊而非内联文字，可视化辨识度更高。(*来源: inferred*)

### 验收要点
- [ ] 悬停文件行即弹出 Tooltip（`onMouseEnter`），跟随鼠标移动（`onMouseMove`），移出消失（`onMouseLeave`）
- [ ] Tooltip 显示：文件名（加粗）、类型、大小、上传时间、解析状态、AI 分类（场景·类别·严重度）、标签
- [ ] 右键/双击弹出自定义上下文菜单，`preventDefault` 阻止浏览器默认右键菜单
- [ ] 单文件菜单：重命名（Pencil 图标）、编辑标签（Tag 图标）、移动到、复制到、删除（红色 Trash2 图标）
- [ ] 多选文件菜单：移动到、复制到、批量删除，顶部显示 "已选 N 项"
- [ ] 文件夹菜单：重命名、删除
- [ ] 菜单点击外部自动关闭（document click 事件监听）
- [ ] 勾选任意复选框后顶部栏显示 "已选 N 项 · 取消"
- [ ] 表头复选框支持全选/取消全选当前可见文件夹+文件

## C4 — KB 详情 — RAG 智能对话面板            [构建: 需要 C2 先完成]

> **截图：** 待从运行系统截取 — 对话面板完整视图：会话选择器 + 检索范围标签 + Markdown 消息列表 + 来源引用 + 输入框。

### 改动内容

右侧可折叠对话面板（通过顶部 "AI 问答" / "收起对话" 按钮切换可见性，由本地 `chatOpen` 状态控制），包含以下区域：

**1. 会话管理栏（顶部）：** 下拉选择器显示当前会话标题（默认 "新对话"），点击展开会话列表（按 `updated_at` 倒序）。每个会话项显示标题和消息数量，当前活跃项有高亮背景。右侧两个按钮：新建会话（MessageSquarePlus 图标）、删除当前会话（Trash2 图标，需确认）。切换知识库时自动加载该 KB 的会话列表，默认选中最近会话。

**2. 检索范围标签（输入框上方）：** 当用户点击文件行或进入文件夹后，输入框上方显示蓝色/青色范围标签：
- 文档范围：`📄 文件名.ext ✕`
- 文件夹范围：`📂 文件夹名 ✕`
- 点击 ✕ 清除范围，恢复全 KB 搜索
- 切换范围后自动清空消息并重新加载会话

**3. 消息列表（中间可滚动区）：**
- 用户消息：右对齐紫色气泡
- AI 回答：左对齐灰色气泡，使用 `ReactMarkdown` + `remarkGfm` 插件渲染（支持标题、列表、加粗、代码块、引用块、表格）
- 流式输出时显示部分内容 + 闪烁光标 `|` 动画
- 每条 AI 回答下方有可折叠的 "来源 (N)" 引用区域，展开显示每条来源：文档名 + 匹配度百分比 + 前 150 字内容预览
- 消息操作按钮（仅 AI 回答显示）：复制（一键复制 Markdown 原文，点击后显示 ✓）、点赞（ThumbsUp 实心/空心切换）、删除（仅限 AI 回答）

**4. 输入框（底部固定）：** 2 行 textarea，placeholder "向 AI 提问..."，Enter 发送（非 Shift）、Shift+Enter 换行。发送中（`isLoading`）时禁用输入。右侧圆形发送按钮（Sparkles 图标）。

**后端 RAG 管线全流程：**
1. 前端通过 `chatStore.sendMessage()` 发送 POST 请求到 `/api/knowledge-bases/{kb_id}/chat/stream`，请求体包含 `question, top_k, session_id, doc_id?, folder_id?`
2. 后端 `retrieve()` 方法执行多路并行检索：
   - **向量检索**（`_vector_search`）：pgvector cosine 相似度（`<=>` 操作符），支持 doc_id/folder_id 过滤
   - **关键词检索**（`KeywordSearchService.search`）：基于 ILIKE 的全文关键词匹配
   - **实体检索**（`EntitySearchService.search`）：匹配实体名称后关联到文档 chunks
3. 可选查询扩展（`rag_enable_query_expansion`）：LLM 生成 2 个查询变体，每变体以 k/2 检索
4. 合并去重（`_merge_results`）：按 chunk_id 去重，按来源加权（vector=1.0, keyword=0.8, entity=0.9）
5. 可选重排序（`rag_enable_reranker`）：CrossEncoder `bge-reranker-v2-m3` 对 top_k×3 候选重打分，取 top_k
6. LLM 生成：使用系统预设的结构化提示词 RAG_SYSTEM_PROMPT（知识管家角色，"抓骨骼→立骨架→填血肉→点睛笔" 四步思维路径）

**SSE 流式输出：** 后端 `chat_stream` 端点返回 `StreamingResponse`（`text/event-stream`）。首帧发送 `session_id` + `sources` 引用列表，后续帧逐 token 发送，末帧 `[DONE]`。前端 `ReadableStream` 逐行解析 SSE 数据帧，实时更新 `streamingContent` 状态。

**会话持久化：** 每次对话回合（用户消息 + AI 回答）自动保存到 `conversations` 表。发送后重新从后端拉取会话列表和消息历史，同步数据库中的消息 ID。

**状态管理（chatStore）：** 所有对话相关状态集中在 Zustand `useChatStore` 中：sessions 列表、currentSessionId、messages 数组、isLoading 标志、streamingContent 流式文本、scopedDocId/DocName 文档范围、scopedFolderId/FolderName 文件夹范围。

### 设计原因

对话面板固定在右侧便于用户在浏览文件的同时进行问答，无需切换页面。会话管理让不同话题的对话互不干扰——用户可以为"产品问题"和"技术问题"分别创建会话。检索范围限定让用户在海量文档中精准定位信息源——当用户知道答案在某份报告中时，限定范围远比全库搜索高效。SSE 流式输出降低 LLM 生成等待焦虑，用户可以在看到前几个字时就开始阅读。Zustand 集中管理对话状态避免了组件间复杂的 prop drilling。(*来源: inferred*)

## C7 — Agent Operator 全局智能导入面板            [构建: 需要 C1 先完成]

> **截图：** 待从运行系统截取 — Operator 面板：KB 选择器 + Agent 对话消息（含工具执行横幅） + 输入框。

### 改动内容

全站右侧独立 Agent Operator 面板（`Operator` 组件，在 `AppLayout` 中与 `<Outlet />` 并列渲染，所有页面均可见），可通过侧边栏折叠按钮控制显示/隐藏。面板组成：

**1. 头部：** "🤖 Agent" 标题 + "AI" 蓝色徽标 + 折叠/展开按钮（PanelRightClose / PanelRightOpen 图标）。面板可折叠为 44px 窄条（只显示头部和展开按钮）。

**2. KB 选择栏：** 标签 "目标库" + 下拉按钮显示当前选中的 KB 名称。点击展开分组下拉（个人 KB / 共享 KB，每组显示名称+文档数），选中项高亮。切换 KB 仅影响 Agent 导入的目标，不影响主内容区的当前 KB。

**3. 消息区（中间可滚动）：**
- **欢迎界面：** 当无消息时显示 Bot 图标 + "你好，我是知识助手" + 介绍文字 + "上传文件" / "导入链接" 两个快捷按钮
- **用户消息：** 右对齐，带 User 头像，可能包含附件卡片（文件名 + 文件大小 / URL 链接）
- **Agent 消息：** 左对齐，带 Bot 头像，支持三种状态：
  - `thinking`（思考中）：旋转 Loader2 + "AI 思考中..."
  - `tool`（工具执行）：🔧 Wrench 图标 + 工具名称横幅
  - `done`（完成）：纯文本回复
  - `error`（出错）：❌ 错误信息

**4. 输入区（底部固定）：**
- 附件按钮（📎 Paperclip 图标），点击弹出小菜单：上传文件 / 导入链接
- 2 行 textarea，placeholder "发消息或粘贴链接..."
- 粘贴完整 URL 到空白输入框时自动识别并发送导入指令
- 发送按钮（Send 图标），发送中或输入为空时禁用
- 导入链接弹窗（URL 输入 + 可选标题 + 确认导入按钮）

**Agent 对话循环（function-calling）：**
- System prompt 定义 Agent 角色（知识库导入助手）和 2 个可用工具：
  - `import_url`：导入网页链接（参数：url）
  - `upload_file`：上传本地文件（无参数，触发文件选择器）
- 用户输入后，前端将对话历史（含 system/user/assistant/tool 消息）发送到 `/api/knowledge-bases/{kb_id}/agent/chat`
- 后端代理到 LLM（DeepSeek/OpenAI），返回 `type: "message"`（文本回复）或 `type: "tool_calls"`（工具调用）
- 前端本地执行工具（`import_url` 调用后端导入接口，`upload_file` 打开 `<input type="file">` 选择器），将结果作为 `tool` 消息追加到对话历史
- 最多 3 轮循环（防止无限调用），文件上传后暂停循环等待用户选择文件

**面板可调整宽度：** 左边缘有拖拽手柄（`.resizeHandle`），mousedown 触发拖拽模式（cursor: col-resize），mousemove 动态更新宽度（`Math.max(280, Math.min(600, ...))`），mouseup 退出拖拽。

### 设计原因

Agent 对话式交互比传统文件上传表单更智能——用户可以粘贴链接、描述需求，Agent 自动判断是导入还是对话。全局面板让用户在任何页面（包括图谱和设置）都能快速导入新内容到指定 KB，无需切换到 KB 详情页。function-calling 协议是 OpenAI 标准，后端仅做透明代理，前端负责工具执行和状态管理——这种架构让工具定义和 UI 交互逻辑紧密耦合在同一端。(*来源: inferred*)

- [ ] 欢迎界面在无消息时显示：Bot 图标 + 介绍 + 两个快捷按钮
- [ ] 用户消息可含附件卡片（文件：名称+大小；链接：URL）
- [ ] Agent 消息支持 thinking / tool / done / error 四种状态渲染
